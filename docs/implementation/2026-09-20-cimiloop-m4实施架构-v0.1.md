# CimiLoop M4 实施架构 v0.1

> 状态：实施基线
>
> 日期：2026-09-20
>
> 范围：在已冻结 M3 上交付 Environment、Release、Deployment、External Operation、Reconciliation 与 bounded Recovery，使同一 Artifact Digest 先在 Test 验证，再经 Human Decision 晋升 Production。本文不实现 Knowledge Closure、Portable Export/Import 或 Change 关闭。

> 实施进度：M4 Task 1–10 已完成。Test 失败走 Repair 不热修、Production 只能晋升已验证同 digest、Unknown 必须核对、预授权 Recovery 保留失败 Deployment，均有自动化测试。全量验收已在 Node.js 24.15.0 + pnpm 12.4.2 基线上通过。

## 1. M4 已实现

- Protocol：Environment、Release、ReleasePackage、Deployment、DeploymentAttempt、VerificationResult、RecoveryStrategy、RecoveryExecution、Reconciliation、ExternalOperation、DevOps Adapter Input/Result；Decision Request type 增加 `release`，required_role_key 增加 `project_owner`；
- Store v5：上述事实只 insert / 状态字段按 Kernel 更新；Outbox 与 Release/Deployment 同事务；M0–M4 无损升级；
- DevOps Command Adapter：argv-only、`shell:false`、Schema 校验输入/结果；Secret 不进 Event/manifest/result；exit 0 不等于业务成功；
- 真实验收环境：文件系统 + 本地 HTTP，不用内存 mock 充当外部目标；
- Test Release：Independent Evaluation ALLOW 后自动授权；QueueDeployment 按 deploy → status → verify 推进；digest 错配产生 Invalid Impact + Blocker；verify 失败产生 Refutes Evidence 与 Repair Work Item；
- Production Release：必须存在同 digest 且 status=verified 的 Test Release；创建后保持 drafted；RequestReleaseDecision / SubmitDecision 只授权该具体 Release；authorization_digest 过期使 Decision 失效；
- 验证门禁：deploy 成功不使 Release verified；必须 status + immediate verify；production verify 失败进入 Recovery，不创建 Repair Work Item；
- Unknown / Reconciliation：未知结果不得自动重试 deploy；RequestReconciliation + RecordReconciliation 映射结论；not_found 阻止重部署；
- Recovery：范围内预授权自动创建新 Deployment + recover attempt，源 Deployment 保持 failed；超范围 / 策略 digest 不匹配 → require_human；
- CLI：`environment register/show`、`release create/show/request-review/queue/authorize-recovery`、`deployment show/record-result/reconcile-*/record-recovery`；
- Workbench Change Room：Delivery 时间线（Environment / Release / Deployment / Unknown / Recovery）与 next action。

## 2. M4 明确未实现

以下能力属于 M5 及之后，不得视为已交付：

- Knowledge Closure、Close/Archive/Cancel/Supersede Change；
- Portable Export/Import 与 Runtime ownership 转移；
- 完整 SPA、通用 Policy 编辑器、登录、实时协作；
- 非 command 的云 DevOps 平台 Adapter；
- staging 环境（Environment kind 仅 test|production）。

## 3. 依赖方向

```text
protocol ← store ← kernel ← devops / orchestrator / cli / workbench
     ↑         ↑              ↑
     └─────────┴─ store-sqlite
                  context / workspace-git / runtime / runtime-claude-code / evaluator
```

Kernel 是 Change 状态、Release 授权和 Gate 的唯一权威。DevOps Adapter、CLI、Workbench 和 Orchestrator 不得直写权威状态；Human Decision 不能直接改 Change 生命周期，只能授权具体 Release 后由 Kernel 重新执行 Gate。

## 4. 关键不变量

1. 测试和生产必须使用同一个 Artifact Digest。
2. Runtime 成功、Artifact 存在或模型自评不能直接通过 Delivery Gate。
3. Test verify 失败走 Repair，不得热修已部署 digest。
4. Production Release 在 Human Decision 之前保持 drafted。
5. 批准只授权该具体 Release；authorization_digest 变化使 Decision 过期。
6. 外部副作用只在数据库事务提交后发生。
7. 对外部结果未知的操作不得盲目重试，必须 Reconciliation。
8. 失败 Deployment 不可变；Recovery 创建新 Deployment/Attempt。
9. Secret 不得进入 Protocol、Event、Context Manifest、日志摘要、Export、错误或测试快照。
10. Change 生命周期保持 Draft → IntentReady → Planned → Executing，不因 Delivery 扩展新生命周期。

## 5. 新增协议对象与命令

新增对象：`Environment`、`Release`、`ReleasePackage`、`Deployment`、`DeploymentAttempt`、`VerificationResult`、`RecoveryStrategy`、`RecoveryExecution`、`Reconciliation`、`ExternalOperation`。

新增 Command：`RegisterEnvironment`、`CreateRelease`、`RequestReleaseDecision`、`QueueDeployment`、`RecordOperationResult`、`RequestReconciliation`、`RecordReconciliation`、`AuthorizeRecovery`、`RecordRecovery`。

主要 Domain Error：`ENVIRONMENT_NOT_FOUND`、`ENVIRONMENT_KEY_CONFLICT`、`RELEASE_NOT_FOUND`、`RELEASE_KIND_ENVIRONMENT_MISMATCH`、`RELEASE_NOT_AUTHORIZED`、`RELEASE_DECISION_NOT_REQUIRED`、`ARTIFACT_DIGEST_MISMATCH`、`PRODUCTION_VERIFICATION_FAILED`、`EXTERNAL_OPERATION_UNKNOWN`、`EXTERNAL_OPERATION_NOT_RETRYABLE`、`RECONCILIATION_NOT_REQUIRED`、`RECOVERY_STRATEGY_NOT_FOUND`、`DEPLOYMENT_NOT_FOUND`、`RECOVERY_REQUIRES_HUMAN`、`RECOVERY_EXECUTION_NOT_FOUND`、`RECOVERY_FAILED`。

## 6. Migration

Project Store 显式版本：v1（M0）→ v2（M1）→ v3（M2）→ v4（M3）→ v5（M4）。从任一已发布 version 升级保持原 ID、revision、event sequence、receipt 与 outbox；重复打开幂等。

## 7. 演示

```powershell
powershell -NoProfile -File scripts/demo-m4.ps1
```

演示在临时 Git 仓库走完 M3 Independent Evaluation ALLOW 后登记 Test Environment，创建自动授权的 Test Release，并按 deploy → status → verify 记录外部结果。期望结果：`release.status = verified`，且 digest 与已评价 Artifact 相同。

## 8. 已知限制

- Change 生命周期未扩展；Delivery 状态机在 Release/Deployment/Operation 上独立运行。
- Solo Release Owner 复用 `project_owner`，未新增独立角色。
- CLI Delivery 路径不调用 workspace-git；外部副作用由 DevOps Adapter / 人工 record-result 回传。
- Evidence Package 在 CreateRelease 时物化一份引用清单，日常 show 仍以查询投影为主。
- Demo 使用 ASCII 文案，避免 Windows PowerShell 5 解析 UTF-8 无 BOM 脚本时断弦。
- Windows 上 CLI 多进程冷启动较慢；M4 CLI 场景测试超时为 90s，断言未降低。
