# CimiLoop M2 实施架构 v0.1

> 状态：实施基线
>
> 日期：2026-09-20
>
> 范围：在已冻结 M1 上交付 Execution、Context 与 Immutable Artifact，使 `Planned` Change 产生有边界 Work Item，在隔离目录中通过首个 Runtime Adapter 执行，并形成可追溯的 Run、Context/Capability Binding、Source Snapshot 与 Artifact。本文不实现 Claim / Evidence、Independent Evaluation、Release、Deployment 或 Portable Export/Import。

> 实施进度：M2 Task 1–10 已完成。`Planned → Work Item → Run → Snapshot → Artifact` 垂直切片、ready 规则、lease/lock、Context Pack、Capability Binding、Claude Code Adapter、Orchestrator 恢复、CLI / Workbench 与 M0/M1→M2 migration 均有自动化测试。全量验收已在 Node.js 24.15.0 + pnpm 12.4.2 基线上通过。

## 1. M2 已实现

- Protocol：Work Item、Agent Run、Context Pack Manifest、Capability Binding、Source Snapshot、Artifact、Lease、Resource Lock、Failure、Blocker；
- Store v3：上述事实表、lease/ready 索引、两连接竞争 claim、过期 reclaim、M0/M1→v3 无损升级且重复打开幂等；
- Kernel ready 规则：`Planned|Executing`、依赖由已完成 execution Work Item 满足、权限/预算/停止条件非空、无开放 Blocker；
- Planning Work Item：仅 `IntentReady` 可创建；已 `Planned`/`Executing` 时幂等空操作，不重复创建；
- Execution Work Item：精确绑定 Contract / Plan / Task / Policy Snapshot；授权边界变化（policy snapshot 不一致）取消开放 execution Work Item 并重建；
- Context Builder 与 Capability Resolver：按 role 最小来源；权限取 actor / work-item / provider 交集；缺失能力产生 Blocker；
- Git Workspace Port：worktree 名称必须为 Change Internal ID；路径必须落在配置根；脏工作区使用 `explicit_dirty_manifest`，不得伪称 git commit；禁止 destructive reset；
- Claude Code Runtime Adapter：输入仅 Work Item、Context manifest 路径、worktree 与 Binding；stdout/stderr 写 Local Files + digest/reference；secret 受控注入并脱敏；exit 0 不是业务成功；未知进程结果生成 Failure/Blocker；
- Orchestrator：claim → context → binding → StartRun → runtime → Heartbeat/Complete/Fail；重启核对 ProcessRegistry，不重复启动已知仍运行进程；CompleteRun 不完成 Task、不把 Work Item 标为 completed、不迁移 Change；
- Artifact：必须绑定 Run / Work Item / Context / Binding / Source Snapshot / SHA-256 digest；同内容可共享 digest；新 candidate 将同 Work Item 旧 candidate 标为 superseded，digest 不变；
- CLI：`scheduler tick`、`work-item list/show/claim/execute`、`run list/show`、`artifact record/show`；
- Workbench Change Room：展示 Task DAG、ready/blocker、Run 的 id/status/log_reference。

## 2. M2 明确未实现

以下能力属于 M3 及之后，不得视为已交付：

- Claim、Evidence、Independent Evaluation、Repair Loop；
- Gate 因 Evidence / Evaluation 推进或回退生命周期；
- Release、Deployment、Recovery、Reconciliation；
- Knowledge Closure 关闭条件与正式 Close/Archive；
- Portable Export/Import；
- 完整 SPA、通用 Policy 编辑器、登录、实时协作；
- 将 Git worktree Port 强制接入 CLI 垂直切片（模块已实现并单测，见第 8 节）。

## 3. 依赖方向

```text
protocol ← store ← kernel ← orchestrator / cli / workbench
     ↑         ↑              ↑
     └─────────┴─ store-sqlite
                  context / workspace-git / runtime / runtime-claude-code
```

Kernel 是 Change 状态迁移和授权判断的唯一权威。CLI、Workbench、Runtime、Orchestrator 和 Git Workspace 不得直写权威状态；外部结果只能通过 Command 回传。

## 4. 关键不变量

1. Runtime 成功、Artifact 存在或进程 exit 0 不能直接通过 Gate，也不能迁移 Change。
2. 重试创建新 Run；授权边界变化创建新 Work Item，不得原地改权限/预算。
3. 一个 Change 使用以 Internal ID 命名的隔离工作目录；Runtime cwd 只能是该路径。
4. Context Pack 与 Capability Binding 不可变；关键 Contract/Policy/permission 变化使 manifest 失效语义留给后续消费方，M2 以 Invalid/Stale 标记表达。
5. Source Snapshot：`git_commit` 必须 `dirty=false` 且含 commit/tree sha；未提交内容必须 `explicit_dirty_manifest` + `dirty=true`。
6. Artifact 只保存 digest、reference 与摘要，不把大型内容复制进 SQLite。
7. Secret 不得进入 Protocol、Event、Context Manifest、日志、CLI JSON 或测试快照。
8. 外部副作用只在事务提交后发生；对未知进程结果执行 FailRun / Blocker，不得盲目重启。
9. Live PID 属于 operator 的 ProcessRegistry，不是权威状态。
10. CompleteRun 只结束 Run；Task / Work Item / Change 保持未完成，等待 M3 Evidence。

## 8. 已知限制

- CLI 垂直切片把 Runtime cwd 设为 `app-data/worktrees/<change-id>` 并 `mkdir`，未强制调用 `workspace-git` 创建真实 `git worktree`；该 Port 已实现、单测覆盖路径越界与脏快照，但未接入 Orchestrator。
- Orchestrator 在磁盘上写入 Context Builder 的 manifest 文件，Kernel `StartRun` 按同一 ID 再持久化权威 Context Pack；二者 ID 对齐，digest 以 Kernel 记录为准。
- Live 进程跟踪使用内存 `ProcessRegistry`；`StartRun.process_reference` 为 `run://${id}`，真实 `pid://` 只存在于 operator 状态。
- `Failure` 是 Protocol 对象，未知 Runtime 结果通过 `FailRun` 落成 Run `unknown` + 开放 Blocker；Store 没有独立 Failure 表。
- Workbench Run 详情只暴露 id / status / `log_reference`，不渲染日志正文。
- `artifact record` CLI 自动写入 `explicit_dirty_manifest` Snapshot，再记录 Artifact，避免演示需要单独 snapshot 命令。
- CompleteRun 不把 Work Item/Task 标完成，因此 scheduler 不会自动放开依赖 Task；这是为 M3 Evidence 预留的正确行为。
- Windows 上 CLI 多进程冷启动较慢；M2 CLI 场景测试超时为 90s，断言未降低。
