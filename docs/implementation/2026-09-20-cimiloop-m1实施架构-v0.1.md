> 状态：实施基线
>
> 日期：2026-09-20

## 1. M1 已实现

- Solo Governance：Change / Intent / Technical Owner 角色与 Assignment；
- Project Policy 与 Policy Snapshot；
- Contract Candidate / Version / Amendment，Risk Profile / Assessment，Knowledge Impact；
- Plan Candidate / Version / Amendment 与 Task DAG；

## 3. 依赖方向

```text
protocol ← store ← kernel ← cli / workbench
     ↑         ↑
     └─────────┴─ store-sqlite
```

Kernel 是 Change 状态迁移和授权判断的唯一权威。CLI 与 Workbench 不得直写 Store 或权威状态。

## 4. 关键不变量

1. Agent Actor 不能承担 Human Owner 或提交正式 Decision。
2. Decision 不直接改状态；保存后 Kernel 按最新事实重新求值 Gate。
3. Decision Request 绑定候选 revision、Profile、Risk、Knowledge、Policy Snapshot 和摘要；输入变化即过期。
4. `request_changes` 保持生命周期并生成 Feedback；`reject` 保持生命周期并进入 `Paused`；只有有效 `approve` 推进生命周期。
5. 正式 Contract / Plan 不可变；候选 revision 不占正式版本号。
6. Plan 精确绑定当前 Contract Version；Task 依赖必须为 DAG。
7. 非 `NoImpact` 知识来源必须由 `kind=knowledge` Task 引用。
8. Current State、Decision / Version、Transition、Event、Outbox、Receipt 原子提交。
9. Read Model 可重建，不能成为授权或状态权威。
10. M1 禁止在 Planned 之后批准 Contract Amendment。

## 7. 演示

```powershell
powershell -NoProfile -File scripts/demo-m1.ps1
```

演示在临时 Git 仓库执行 `init → governance → create → contract approve → plan approve → room/timeline`，最终 Change 为 `Planned`。Windows PowerShell 5 通过 `Start-Process` 将 CLI 标准输出重定向到 UTF-8 文件后再解析 JSON，避免中文 `display_name` 被控制台代码页损坏。

## 8. 已知限制

- Workbench 是 Node `http` SSR 基础页，不是完整产品工作台。
- Inbox 摘要按 Feature 文案投影，未做多 Profile 文案分化。
- 没有独立的 Amendment 撤回 Command；新提案会将仍开放的 Amendment 标为 withdrawn。
- 开发分支为 `codex/v1-complete`（总执行计划要求），而不是 M1 单里程碑计划中的 `codex/m1-intent-plan-decision`。
- Windows 上每次 CLI 进程冷启动较慢；M1 CLI 垂直切片测试超时从 30s 调整为 90s，断言未降低。
